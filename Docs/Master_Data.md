# ข้อมูลอ้างอิงและตั้งค่าพื้นฐาน (Master Data / Lookup Data)

ชุดข้อมูลพื้นฐาน (Reference Data) ที่ระบบ Wae Jer Logistic ใช้อ้างอิง ตามค่าที่ปรากฏจริงในโค้ด

---

## 1. สถานะร้านค้า — `stores.status`

| รหัส | คำอธิบาย |
| :--- | :--- |
| `UNSURVEYED` | ค่าเริ่มต้น — ยังไม่มีการเยี่ยม/สำรวจ |
| `SUCCESS` | เยี่ยม/สำรวจสำเร็จ หรือมีการขายแล้ว (ตั้งอัตโนมัติเมื่อบันทึกการขาย) |
| `NOT_FOUND` | พนักงานลงพื้นที่แล้วไม่พบร้านตามพิกัด (ถูกซ่อนจากฝั่ง Driver) |

## 2. สถานะการตรวจสอบผลสำรวจ — `stores.verification_status`

| รหัส | คำอธิบาย |
| :--- | :--- |
| `PENDING` | ค่าเริ่มต้น — รอแอดมินตรวจสอบ |
| `APPROVED` | แอดมินอนุมัติรูปถ่าย/ข้อมูลการสำรวจ |
| `REJECTED` | แอดมินปฏิเสธ (เมื่อ Reject ระบบตั้ง `status` กลับเป็น `UNSURVEYED`) |

## 3. สถานะการเยี่ยมร้าน — `visits.status`

| รหัส | คำอธิบาย |
| :--- | :--- |
| `SUCCESS` | เยี่ยม/สำรวจ/ขายสำเร็จ |
| `CLOSED` | ไปถึงแล้วแต่ร้านปิด |
| `FAILED` | เยี่ยมไม่สำเร็จ / ร้านปฏิเสธ |

## 4. สถานะการทำงานของพนักงาน — `drivers.work_status`

| รหัส | คำอธิบาย |
| :--- | :--- |
| `ONLINE` | กำลังปฏิบัติงาน |
| `OFFLINE` | ค่าเริ่มต้น — ไม่ได้ปฏิบัติงาน |

## 5. สถานะยานพาหนะ — `vehicles.status`

| รหัส | คำอธิบาย |
| :--- | :--- |
| `AVAILABLE` | ค่าเริ่มต้น — พร้อมใช้งาน |
| `MAINTENANCE` | ซ่อมบำรุง |

## 6. ประเภทคลังสินค้า — `inventory.location_type`

| ประเภท | location_id | คำอธิบาย |
| :--- | :--- | :--- |
| `MASTER` | `''` (ค่าว่าง) | คลังสินค้าหลักของบริษัท |
| `VEHICLE` | รหัสรถ เช่น `V-01` | สต็อกบนรถแต่ละคัน |

## 7. ประเภท Stock Transaction — `stock_transactions.transaction_type`

| ประเภท | คำอธิบาย | ผลกับสต็อก |
| :--- | :--- | :--- |
| `TRANSFER` | โอนจากคลังหลักขึ้นรถ | MASTER ลด, VEHICLE เพิ่ม |
| `SALE` | ขายสินค้าออก | VEHICLE ลด |
| `RETURN` | คืนสินค้ากลับคลัง | VEHICLE ลด, MASTER เพิ่ม |

> ปัจจุบัน `/api/inventory/transfer` บันทึกเฉพาะประเภท `TRANSFER`; การขายตัดสต็อกตรงในตาราง `inventory` ภายในทรานแซกชันของ `/api/sales`

## 8. สถานะเป้าหมายสำรวจ — `survey_targets.status`

| รหัส | คำอธิบาย |
| :--- | :--- |
| `ACTIVE` | ใช้งานอยู่ (แสดงบนแผนที่) |
| `ARCHIVED` | ถูกลบ (soft-delete) |

## 9. หมวดหมู่และสินค้าตั้งต้น (Seed)

หมวดหมู่ที่ seed เมื่อฐานข้อมูลว่าง (`server/index.ts` → `seedProducts`):
1. เครื่องดื่ม
2. ขนมขบเคี้ยว
3. ของใช้ส่วนตัว

สินค้าตัวอย่าง 6 รายการ (SKU: `DR-001`, `DR-002`, `SN-001`, `SN-002`, `PC-001`, `PC-002`)

> เมื่อนำเข้าจาก POS: `sku` จะกลายเป็นค่า `pos.products.id`, หมวดหมู่สร้างตามชื่อจาก POS, สินค้าที่ไม่มีหมวดหมู่ใช้ชื่อ "ไม่มีหมวดหมู่"

## 10. ข้อมูลพื้นที่ (Zones)

- Seed จาก `korat_zones.json` — อำเภอ 32 อำเภอ + ตำบลของจังหวัดนครราชสีมา
- **ตำบล** ใช้ `id` = ค่าจริง **+ 10000** เพื่อไม่ชนกับ id อำเภอ
- `parent_id` ของตำบลชี้ไปยัง id อำเภอ
- `src/constants/locations.ts` มี `KORAT_SUBDISTRICTS` (map อำเภอ → รายชื่อตำบล) สำหรับ dropdown ฝั่ง client

# โครงร่างสำหรับการนำเสนอ (Presentation Outline)
## ระบบ Wae Jer Logistic (Cashvan & Survey Management)

โครงร่างสำหรับเตรียมสไลด์นำเสนอโปรเจกต์ — ปรับปรุงให้ตรงกับฟีเจอร์ปัจจุบัน

---

## สไลด์ที่ 1: ปัญหาและที่มา (Introduction & Pain Points)
**ทำไมต้องมีระบบ Wae Jer Logistic?**
- ปัญหาเดิม: จดออเดอร์บนกระดาษ ข้อมูลสูญหาย/สรุปยอดผิด, ตรวจสต็อกบนรถยาก, ส่วนกลางไม่รู้ว่าพนักงานลงพื้นที่จริงหรือไม่ อยู่จุดไหน
- ทางแก้: Digital Transformation ทั้งกระบวนการ + ติดตามรถด้วย GPS เรียลไทม์ + แยกระบบ Mobile (พนักงาน) / Desktop (ผู้จัดการ)

---

## สไลด์ที่ 2: ภาพรวมระบบ (System Overview)
- ระบบบริหารหน่วยรถ (Cashvan) + สำรวจร้านค้า พื้นที่จังหวัดนครราชสีมา
- ทำงานผ่าน Web ไม่ต้องติดตั้งแอป — พนักงานเข้าผ่าน LINE
- ข้อมูลเชื่อมต่อเรียลไทม์ระหว่างคนขับรถและสำนักงาน
- จัดการ 3 เสาหลัก: **พนักงาน + ตำแหน่ง GPS / สินค้าและสต็อก 2 ระดับ / พิกัดร้านค้ารายอำเภอ-ตำบล**
- เชื่อมกับระบบ POS (line-commerce) เพื่อใช้แคตตาล็อกสินค้าจริง

---

## สไลด์ที่ 3: ฟีเจอร์แยกตามบทบาท (Key Features by Role)

### พนักงานขับรถ (Driver) — Mobile-first
- **เข้าระบบผ่าน LINE** + ผูกบัญชีครั้งเดียว
- **ติดตาม GPS อัตโนมัติ** — ส่งพิกัดทุก 30 วินาที + บันทึกเส้นทางรายวัน
- **แผนที่ + รายการร้าน** — กรองตามอำเภอ/ตำบล, แท็บ ยังไม่ไป/เสร็จแล้ว
- **เช็คอิน + สำรวจ** — ตรวจระยะ GPS, ถ่ายรูปขึ้นคลาวด์, เพิ่มร้านใหม่
- **บันทึกการขาย** — ตัดสต็อกบนรถอัตโนมัติ
- **ปิดยอด/นับสต็อก** — เทียบยอดคาดหวังกับของจริง

### ผู้จัดการ (Admin) — Desktop-first
- **Dashboard** — ความคืบหน้าการสำรวจรายอำเภอ (วันนี้/สัปดาห์/เดือน)
- **Fleet Tracking (Map Overview)** — ตำแหน่งรถเรียลไทม์ + เส้นทางย้อนหลัง + ขอบเขตอำเภอ GeoJSON + geofence
- **คลังสินค้า 4 แท็บ** — สต็อกรถ / คลังหลัก / แคตตาล็อก / อ้างอิง POS (+ ปุ่มนำเข้าจาก POS)
- **Van Transfer** — โอนสต็อกคลังหลัก → รถ พร้อมประวัติ
- **Survey Audit** — อนุมัติ/ปฏิเสธผลสำรวจ
- **Sales Reports** — รายบิล + เปรียบเทียบผลงานพนักงาน + กระทบยอด

## สไลด์ที่ 4: เทคโนโลยีเบื้องหลัง (Technology Stack)
- **Frontend:** React 19, Vite 6, TypeScript, Tailwind CSS 4
- **Maps:** Leaflet + OpenStreetMap + GeoJSON ขอบเขตอำเภอโคราช (ไม่มีค่าลิขสิทธิ์แพง)
- **Backend:** Node.js + Express 4 (รันด้วย tsx)
- **Database:** MySQL 8.x (`WH_logistic`) + อ่านฐานข้อมูล `pos` ของ line-commerce
- **Auth:** LINE LIFF (Driver), SHA-256 + Context (Admin)
- **Image:** Cloudinary (มี fallback บีบอัด Base64)
- Deploy: VPS self-hosted (Nginx reverse proxy + pm2)

---

## สไลด์ที่ 5: ประโยชน์ทางธุรกิจ (Business Value)
1. **ลดข้อผิดพลาด** — เลิกกระดาษ ตัดปัญหายอดไม่ตรง/สต็อกหาย
2. **ประหยัดเวลา** — พนักงานสรุปยอดง่าย แอดมินไม่ต้องรวมบิลเอง
3. **ตรวจสอบได้ / โปร่งใส** — พิกัด GPS จริง + เส้นทางย้อนหลัง + ภาพถ่ายยืนยัน
4. **ใช้ข้อมูลสินค้าจริงจาก POS** — แคตตาล็อกและสต็อกเริ่มต้นตรงกับหน้าร้าน
5. **พร้อมเติบโต** — ข้อมูลเป็นระบบ ต่อยอด Data Analytics ได้

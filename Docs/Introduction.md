# บทนำ (Introduction)

## 1. ที่มาและความสำคัญของระบบ Wae Jer Logistic

ธุรกิจโลจิสติกส์และการกระจายสินค้า (Distribution) โดยเฉพาะในรูปแบบหน่วยรถเร่ หรือ **Cashvan** มีความซับซ้อนสูง เนื่องจากต้องจัดการทรัพยากรหลายด้านพร้อมกัน ทั้งพนักงานขับรถ สินค้าในสต็อกบนรถ แผนที่การเดินทางเข้าถึงร้านค้า และการสรุปยอดขายในแต่ละวัน

ก่อนหน้านี้การจัดการข้อมูลเหล่านี้มักทำผ่านกระดาษหรือแอปแชททั่วไป ทำให้เกิดความล่าช้า ข้อมูลตกหล่น และยากต่อการตรวจสอบของส่วนกลาง (Admin/Manager)

ระบบ **Wae Jer Logistic (Cashvan & Survey Management)** ถูกสร้างขึ้นเพื่อทำ **Digital Transformation** ให้กับกระบวนการทั้งหมด โดยเน้นพื้นที่ปฏิบัติงานในจังหวัดนครราชสีมา (โคราช) ให้การนำสินค้าไปเสนอขายหน้าร้าน (Cashvan) และการเก็บข้อมูลสภาพร้านค้า (Survey) ทำได้อย่างเป็นระบบ ตรวจสอบได้แบบเรียลไทม์ พร้อมติดตามตำแหน่งรถจริงผ่าน GPS

## 2. กลุ่มเป้าหมายผู้ใช้งาน (Target Users)

1. **ผู้จัดการ / ผู้ดูแลระบบ (Admin)**
   - ทำงานในสำนักงาน (Back Office) ผ่านคอมพิวเตอร์
   - ต้องการเห็นภาพรวมการทำงานของพนักงานขับรถและความคืบหน้าการสำรวจรายอำเภอ
   - ต้องการติดตามตำแหน่งรถแบบเรียลไทม์และเส้นทางย้อนหลัง
   - ต้องการจัดการสินค้า/สต็อก และตรวจสอบผลสำรวจร้านค้า

2. **พนักงานขับรถ / เซลส์หน่วยรถ (Driver)**
   - ลงพื้นที่จริง ใช้งานผ่านมือถือในแอป LINE
   - ต้องการเครื่องมือที่ใช้งานง่าย: เข้าระบบผ่าน LINE, แผนที่นำทาง, แคตตาล็อกสินค้าบนรถ
   - ต้องการให้การเช็คอิน บันทึกยอดขาย และปิดยอดปลายวันเป็นเรื่องง่าย

## 3. ขอบเขตเอกสาร

เอกสารชุดนี้เป็นคู่มือและข้อกำหนดทางเทคนิค (Technical Specification) สำหรับการพัฒนา บำรุงรักษา และต่อยอดระบบ ครอบคลุม:

- โครงสร้างและสถาปัตยกรรมของระบบ (System Architecture)
- การออกแบบฐานข้อมูล (ER Diagram & Data Dictionary)
- ข้อมูลจำเพาะทางเทคนิคและ API (API Documentation)
- กระบวนการทำงานหลัก (System Workflows, Admin/Driver Workflow)
- การเชื่อมต่อระบบ POS และการติดตาม GPS (POS Integration, Fleet Tracking)
- ขั้นตอนและสภาพแวดล้อมในการพัฒนา และการติดตั้งใช้งาน

## 4. นิยามศัพท์ (Glossary)

| คำศัพท์ | คำจำกัดความ |
| :--- | :--- |
| **Cashvan** | รูปแบบการขายสินค้าโดยนำสินค้าขึ้นรถแล้ววิ่งไปขายตามร้านค้าย่อย |
| **Store Survey** | การเก็บข้อมูลสถานะร้านค้าย่อย เช่น พิกัด รูปหน้าร้าน สถานะเปิด/ปิด |
| **Van Stock** | สต็อกสินค้าที่อยู่บนรถแต่ละคัน (แยกตาม `location_id` = รหัสรถ) |
| **Master Inventory / Master Warehouse** | คลังสินค้าหลักของบริษัท (`location_type = 'MASTER'`) |
| **Van Transfer / Refill** | การโอนสต็อกจากคลังหลักขึ้นรถ (endpoint `/api/inventory/transfer`) |
| **Check-in** | การยืนยันตำแหน่ง GPS ของพนักงานเมื่อถึงร้านค้า (มีการตรวจระยะแบบ Haversine) |
| **GPS Trail / Breadcrumb** | เส้นทางการเดินทางของพนักงานที่บันทึกเป็นจุดพิกัดรายวัน (`gps_tracks`) |
| **Driver Location** | ตำแหน่งล่าสุดของพนักงานแบบเรียลไทม์ (`driver_locations`, upsert รายคน) |
| **Survey Target / Geofence** | พื้นที่เป้าหมายสำรวจรูปวงกลม (จุดศูนย์กลาง + รัศมี) ที่มอบหมายให้พนักงาน |
| **LINE LIFF** | LINE Front-end Framework ใช้เปิดเว็บแอปในแอป LINE และดึงโปรไฟล์ผู้ใช้ |
| **Bind (ผูกบัญชี)** | การจับคู่ `line_user_id` ของพนักงานกับรายชื่อ Driver ในระบบ (ทำครั้งเดียว) |
| **POS (line-commerce)** | ระบบขายหน้าร้านที่มีฐานข้อมูล `pos` อยู่บนเซิร์ฟเวอร์ MySQL เดียวกัน — Cashvan อ่านอย่างเดียว |
| **Zone** | ข้อมูลอำเภอ/ตำบลของโคราช เก็บในตาราง `zones` (subdistrict id บวก offset 10000) |
| **Verification Status** | สถานะการตรวจสอบผลสำรวจโดยแอดมิน: PENDING / APPROVED / REJECTED (แยกจาก `stores.status`) |
